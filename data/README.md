# data

- `raw/` : 提供された元データ（原則として編集しない）
- `edited/` : `npm run data:process`（変換コードは `converter/`、Rust）で生成・加工したデータ。アプリはここから読み込む（`public/data/` へコピーされる）

## raw: 基盤地図情報 基本項目（国土地理院）

[基盤地図情報ダウンロードサービス](https://service.gsi.go.jp/kiban/) の GML 形式 zip を置く。

- ダウンロードした zip（例: `20261102050008481-001.zip`）は中に `FG-GML-*.zip` がまとめて入っているので、同名のフォルダ（例: `raw/20261102050008481-001/`）に展開する
- 変換コードは `raw/` 以下を再帰的に探し、`FG-GML-*.zip` だけを読む（ダウンロードした外側の zip は無視される）
- 現在の `edited/` は全国データ（05: 4891メッシュ、12: 2347メッシュ）から作っている

- ファイル名: `FG-GML-{2次メッシュ番号}-{項目番号}-{日付}.zip`
- 同じメッシュ・項目が複数ある場合は日付の新しいものを使う
- 座標系: JGD2024 緯度経度（GML 上は「緯度 経度」順）

| 項目番号 | 内容 | 使用する地物 |
| --- | --- | --- |
| `05` | 行政区画 | `AdmArea`（市区町村ポリゴン。2次メッシュ単位で分割されている） |
| `12` | 町字界 | `CommBdry` のうち `大字・町・丁目界`（線）、`CommPt`（大字・町・丁目の代表点） |

`AdmBdry` / `AdmPt` など上記以外の地物と、その他の項目番号は現在使っていない。

## edited

座標はすべて GeoJSON（経度・緯度、JGD2024 をそのまま WGS84 相当として扱う）。

```
edited/
├── index.json                 都道府県 → 市区町村の一覧（名称・コード・範囲・面積など）
├── offices.json               市区町村コード → 庁舎の位置 [経度, 緯度]（距離感覚モードの起点。`npm run data:offices` で作る）
├── towns-index.json           市区町村コード → 町・大字名の一覧（クイズで同じ名前の地名を探すのに使う）
├── prefectures.geojson        都道府県（全体表示用に簡略化）
├── municipalities.geojson     市区町村（全体表示用に簡略化）
└── prefectures/
    └── {都道府県コード}/
        └── {市区町村コード}/
            ├── boundary.geojson   市区町村ポリゴン（詳細、約0.1m精度）
            └── towns.geojson      町・大字の区域と名称位置（12 のデータがある市区町村のみ）
```

型定義は `src/types/index.ts` を参照。

### 加工内容

変換コードは `converter/`（Rust）。手順の詳細と実装上の注意はリポジトリ直下の `CLAUDE.md` の「地区割の方法」を参照。

- メッシュ単位の `AdmArea` を団体コードごとに統合（dissolve）して市区町村ポリゴンにする
- 市区町村を都道府県コード（団体コード上2桁）で統合して都道府県ポリゴンにする
- 全体表示用は隣接境界を保ったまま簡略化（許容30m）し、面積2,000m²未満の小島・穴を除く
- 町字界線は線上の頂点がどの市区町村ポリゴン内にあるかで振り分ける。湾内など陸域ポリゴン外の線は、端点でつながる線と同じ市区町村にする
- 町字代表点は `admCode` で振り分ける（`00000` など不明なものは位置で判定）
- 町・大字の区域（市区町村の1段下のまとまり）は次の手順で作る
  1. 市区町村ポリゴンを町字界線で切り分ける（他の線とつながっていない線端は 1m 延ばして、わずかな隙間でも切れるようにする）
  2. 区域内の代表点の名称から「〜丁目」を除いた名前（例: 枝松一丁目〜六丁目 → 枝松）を付ける。複数の名前があれば最も多いもの
  3. 同じ名前の区域を統合する。代表点を含まない区域（町字データの無い範囲など）は出力しない

### 注意

- 面積・ポリゴンは **収録したメッシュの範囲内** のもの。メッシュが欠けている市区町村は一部のみになる
- 行政区画は 1/25000 相当、町字界は 1/2500 相当で精度が異なる
- 町・大字の区域は線から組み立てているため、元データで境界線が欠けている箇所では隣の町と1つの区域になる（例: 松山市の三津三丁目が三津ふ頭と同じ区域になる）
- 除くのは丁目番号だけで、甲・乙や東西南北などは名称の一部として残す（朝倉甲と朝倉乙、余戸中と余戸南は別の区域）

## sources: 外部データ（変換コードを通さず、スクリプトで edited に取り込むもの）

`sources/` のファイルは出どころごとに写したもの。`npm run data:process` のあとに `npm run data:offices` で `edited/offices.json` を作る（`scripts/build-offices.ts`）。

| ファイル | 内容 | 出どころ |
| --- | --- | --- |
| `sources/offices-p05.json` | 市町村役場（施設分類が「本庁」）の位置 | 国土数値情報「市町村役場等及び公的集会施設」P05-10（2010年）。国土交通省。**商用利用不可**（出どころの有償刊行物の条件） |
| `sources/offices-extra.json` | P05 に無い区（熊本市の5区）の区役所の位置 | © OpenStreetMap contributors（ODbL） |

- P05 は2010年のデータなので、その後に市になった町村（滝沢・富谷・白岡・大網白里・野々市・長久手・那珂川）と浜松市の新しい区は、旧コードの庁舎を引き継ぐ（`scripts/offices.ts` の `SUCCESSORS`）
- 庁舎が決まらない市区町村（北方領土の村、所属未定地）は `offices.json` に含めない
